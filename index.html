Bien démarrer un projet

Ton mémo de démarrage pour retrouver rapidement les commandes, les fichiers et les étapes essentielles avant de coder.

TypeScript

Mise en place de l’environnement et configuration du projet, selon les pages 1 et 2 du TP1.

Configuration de départ

Étape 1 — Outils à installer

À faire une seule fois sur la machine.

1
Installer Node.jsVersion LTS recommandée : nodejs.org. Vérifier l’installation :
node -v
npm -v
2
Installer TypeScript en global
npm install -g typescript
tsc -v

Étape 2 — Création du projet

Depuis le terminal, dans le dossier où tu ranges tes projets.

mkdir gestion-notes-etudiants
cd gestion-notes-etudiants
npm init -y
npm install --save-dev typescript ts-node nodemon @types/node
npx tsc --init
Le nom gestion-notes-etudiants est celui utilisé dans le TP. Tu peux l’adapter au nom de ton nouveau projet.

Étape 3 — Configuration TypeScript

Remplacer le contenu du fichier tsconfig.json par :

{
  "compilerOptions": {
    "target": "ES2020",
    "module": "commonjs",
    "outDir": "./dist",
    "rootDir": "./src",
    "strict": true,
    "esModuleInterop": true,
    "sourceMap": true,
    "noImplicitAny": true,
    "strictNullChecks": true
  },
  "include": ["src/**/*"],
  "exclude": ["node_modules", "dist"]
}

Étape 4 — Scripts dans package.json

Ajouter la propriété scripts dans le fichier existant package.json (sans effacer les autres propriétés).

"scripts": {
  "build": "tsc",
  "start": "node dist/index.js",
  "dev": "ts-node src/index.ts",
  "watch": "nodemon --exec ts-node src/index.ts"
}

Compiler et exécuter le projet

Depuis la racine du projet, après avoir créé tes fichiers dans src/.

1
Compiler les fichiers TypeScriptLa commande npx tsc utilise le fichier tsconfig.json et compile les fichiers inclus dans src/.
npx tsc
2
Exécuter le JavaScript généréAvec la configuration de cette fiche, le résultat est placé dans dist/.
node dist/index.js
S’il y a plusieurs fichiers .ts, cela fonctionne aussi : npx tsc compile les fichiers inclus dans src/**/*. Les fichiers JavaScript correspondants sont générés dans dist/. Lance ensuite le fichier d’entrée du programme (ici index.js). Les fichiers utilisés entre eux doivent être reliés avec des imports/exports.
Tu peux aussi utiliser npm run dev avec le script configuré plus haut pour exécuter directement src/index.ts avec ts-node, sans étape de compilation manuelle.

Étape 5 — Structure du projet

Créer le dossier source et le fichier d’entrée.

mkdir src
touch src/index.ts
gestion-notes-etudiants/ ├── src/ │ └── index.ts ├── dist/ ├── package.json └── tsconfig.json

Étape 6 — Débogage VS Code

Créer le fichier .vscode/launch.json :

{
  "version": "0.2.0",
  "configurations": [
    {
      "type": "node",
      "request": "launch",
      "name": "Déboguer TypeScript",
      "runtimeArgs": ["-r", "ts-node/register"],
      "args": ["${workspaceFolder}/src/index.ts"],
      "console": "integratedTerminal"
    }
  ]
}
Ces étapes reprennent la configuration de départ de ton document TypeScript. Une fois le projet configuré, tu peux conserver cette structure et l’adapter à tes exercices.

Java — Compiler et lancer

Les commandes de compilation et d’exécution présentées dans la fiche « Compilation Java & GitHub ».

Compilation Java

Structure du projet

Exemple de structure utilisée dans la fiche.

HelloMobility/ ├── src/ │ ├── mobility/ │ │ └── HelloMobility.java │ └── Main.java └── bin/
Depuis la racine du projet, le package doit correspondre à l’arborescence des dossiers.

1 — Créer le dossier de sortie

À faire si le dossier bin n’existe pas.

mkdir bin

2 — Compiler les fichiers source

La commande compile les deux fichiers et place les fichiers compilés dans bin.

javac -d bin src/mobility/HelloMobility.java src/Main.java
Oui, cette méthode fonctionne avec plusieurs fichiers Java : indique tous les fichiers .java nécessaires dans la commande. Le compilateur génère autant de fichiers .class que nécessaire dans bin/ (y compris les classes des packages).
On compile les fichiers .java, pas les fichiers .class à la main. Si les sources sont nombreuses, tu peux aussi compiler tous les fichiers source en une seule commande adaptée à leur arborescence.

3 — Lancer la classe principale

Exécuter la classe Main depuis le dossier de sortie.

java -cp bin Main
À retenir : .java = fichier source ; .class = bytecode compilé. Le package doit correspondre à l’arborescence.

Git & GitHub

Initialiser un dépôt, publier le projet, synchroniser les changements et gérer l’historique.

Gestion de versions

1 — Initialiser Git

Depuis la racine du projet.

git init

Créer un fichier qui s’appelle exactement .gitignore à la racine du projet (au même niveau que src/ et bin/).

Attention : ces lignes ne sont pas des commandes à taper dans le terminal. Ouvre/crée le fichier .gitignore dans VS Code, puis écris une règle par ligne :
bin/
*.class
.vscode/
  • bin/ : ignore tout le dossier de compilation bin.
  • *.class : ignore tous les fichiers compilés qui se terminent par .class.
  • .vscode/ : ignore le dossier de configuration locale de VS Code.
Enregistre le fichier. Git ne proposera alors pas ces éléments non suivis lors de l’ajout avec git add ..

2 — Premier commit

Préparer et enregistrer la première version.

git status
git add .
git commit -m "Initial Java project"

3 — Relier le dépôt à GitHub et publier

Créer un dépôt vide sur GitHub, copier son URL, puis exécuter à la racine du projet :

git remote add origin URL_DU_DEPOT
git remote -v
git branch -M main
git push -u origin main
Remplacer URL_DU_DEPOT par l’URL réelle du dépôt GitHub.

4 — Routine de mise à jour

Récupérer, vérifier, préparer, enregistrer et envoyer les changements.

git pull
git status
git add .
git commit -m "Description claire"
git push

5 — Historique et annulation

Consulter l’historique ou annuler des changements.

git log --oneline
git restore --source=ID -- src/Main.java
git revert ID_DU_COMMIT
git restore peut écraser les modifications locales du fichier. git revert crée un nouveau commit qui annule les effets d’un commit précédent.

6 — Branches et bons réflexes

git switch -c nom-branche
git switch main
git merge nom-branche
  • Vérifier git status avant un commit.
  • Ne pas versionner bin/ ni les fichiers .class : ils se régénèrent.
  • Vérifier la branche active avant un merge.
Compiler→Vérifier→add→commit→push
Remplacer URL_DU_DEPOT et ID_DU_COMMIT par les vraies valeurs.
